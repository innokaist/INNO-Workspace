# 통합 마스터 병렬 분배 설계 — 검토안

상태: 설계 검토용. 현재 배포 기능은 순차 인계이며 이 문서의 병렬 기능은 아직 구현하지 않았다.

## 목표와 권장 방식

마스터가 요청을 이해하고 독립 작업을 나누어 제공자·모델·검증 기준을 먼저 기록한 다음, Codex와 Claude 작업을 병렬 실행하고 결과를 검토·통합한다. 완료한 하위 작업은 장애 복구나 다른 하위 작업 재시도 때문에 다시 실행하지 않는다.

권장 방식은 D1에 상위·하위 작업과 배정 세대를 영구 기록하는 조정기다. 마스터 프로세스를 기다리게 유지하는 방식은 구현이 단순하지만 토큰과 세션·PC 생존에 의존한다. 제공자별 세션을 무제한 병렬 실행하는 방식은 처리량이 높아도 구독 사용량과 실패 복구를 통제하기 어렵다. 따라서 마스터는 배정 후 종료하고, 검토할 결과가 모이면 새 실행권으로 다시 시작한다.

## 독립 플랫폼 원칙

INNO Workspace는 완결된 독립 플랫폼이다. NanoLab·Prism·RefAtlas·Scheduler·Analytics·Ledger는 필요할 때만 사용하는 선택 도구다. 상위 작업·분배·실행·기록·결과 통합은 이 앱들의 설치, 로그인, 데이터 형식, 연결 상태에 의존하지 않는다. 마스터는 요청 목적에서 출발하며 특정 앱 사용을 기본 경로로 강제하지 않는다. 선택 연동의 실패는 해당 도구가 필요한 하위 작업에만 영향을 주며 일반 작업은 계속 사용할 수 있어야 한다. 검증에는 모든 선택 연동을 끈 상태의 요청→분배→실행→결과 통합을 반드시 포함한다.

## 첫 구현 범위

- 클라우드 연결 작업, 독립 하위 작업 정확히 2개, Codex 1개와 Claude 1개로 시작한다.
- 단순 요청·명시적인 위임 금지 요청은 직접 처리한다.
- 원문 첨부·URL 참조가 있는 작업은 이번 범위에서 자동 병렬 분배하지 않는다. 원본 임시 전달은 다음 독립 단계다.
- 하위 작업은 재분배·제공자 인계를 못 한다. 해당 배정 범위의 도구 실행과 결과 생성만 한다.
- 마스터의 해석 및 최종 통합은 현재 선택된 강한 모델을 유지한다. 병렬화 자체가 유용하지 않으면 배정을 거절하고 직접 처리한다.
- 한 배정 묶음당 검토 실패 하위 작업의 추가 시도는 1회, 구독 한도·인증 실패는 자동 재시도하지 않는다.
- 현재 무료 Cloudflare 자원 및 기존 구독만 사용한다. API 키·유료 초과 사용은 추가하지 않는다.

## 모델 배정의 실제 적용 범위

배정 레코드에는 provider, requestedModel, effort, sufficientReason, acceptanceCriteria를 필수로 남긴다. Codex 모델·effort는 실행 직전 model/list에 있는지 확인한 뒤 실제 CLI 인수에 전달한다. 지원이 바뀌면 임의 치환하지 않고 배정을 보류한다.

현재 Claude Routine의 최상위 모델을 호출마다 지정하는 계약은 구현돼 있지 않다. 이 제한을 숨기지 않는다. 첫 구현에서는 Routine 마스터가 배정된 Claude 네이티브 하위 모델을 명시하여 한 역할을 수행하게 하고, 마스터의 추가 비용도 실행 구조에 표시한다. 플랫폼이 관측하지 못한 실제 모델 ID나 하위 토큰을 추정해 채우지 않는다. 이 우회 실행 구조의 비용이 분배 이득보다 크면 마스터 직접 처리로 결정해야 한다.

## 상태와 기록

상위 작업에 delegation={batchId, sourceExecutionId, sourceGeneration, masterProvider, state, children[]}를 기록한다. 각 하위 작업은 별도의 실행권과 parentTaskId/batchId를 가진다. 하위 작업 ID와 배정 조건은 서버에서 만든다. 일반 createTask나 기록 가져오기로 관계를 위조하지 못하게 한다.

상위 단계: running → waiting_children → queued_for_review → running(review) → completed 또는 waiting_user.
하위 단계: queued → running → completed / failed / waiting_quota / waiting_connection / paused / cancelled.

상위 상태와 두 하위 레코드 생성은 D1의 한 원자적 배치로 반영한다. 같은 배정 응답의 재전송은 같은 하위 작업을 반환한다. 중간 실패로 연결되지 않은 하위 작업을 남기지 않는다. 파일 본문은 기존 결과 저장 규칙을 따르고 입력 원본은 복제하지 않는다.

## 실행과 재개

Claude 시작 및 Codex 데스크톱 claim 모두 상위 작업 상태·batchId를 원자적으로 검증한다. 상위 대기 중에는 모델을 반복 호출해 폴링하지 않는다. 서버 조정기가 완료 콜백과 제한된 복구 점검으로 상태를 확인한다. 같은 상위 검토 실행권은 한 번만 발급한다.

PC가 꺼졌을 때 Claude가 끝나도 Codex 하위 작업은 대기한다. UI는 부분 완료와 대기를 구분한다. 완료한 Claude 작업은 재실행하지 않는다. 할당 후 외부 호출 직전 서버가 종료되는 구간은 exactly-once를 주장하지 않으며, 호출 여부가 불확실하면 자동 새 세션 생성 대신 확인 필요 상태로 둔다.

상위 일시정지·취소는 새 하위 claim과 결과 채택을 막는다. 이미 시작된 원격 Claude 세션을 플랫폼이 즉시 종료할 수 있다고 표시하지 않는다. 실행권을 회수해 이후 콜백은 차단한다. 재개는 완료 결과를 보존하고 미완료 작업만 새 실행권으로 진행한다.

상위에 새로운 사용자 지시가 오면 기존 배정 세대를 무효화한다. 이전 세대의 늦은 결과를 새 지시에 합치지 않는다. 새 지시로 재계획할 때 이미 생성된 결과의 재사용 여부는 마스터가 판단한다.

## 결과 검토와 생성 파일

마스터는 하위 작업의 완료 상태를 검증 성공으로 간주하지 않는다. 각 acceptanceCriteria에 대해 통과/미통과/확인 불가 및 근거를 남겨야 완료할 수 있다. 상충하는 결과는 근거를 대조하고, 판단에 필요한 자료가 없으면 선택지 또는 자료 재연결을 요청한다.

상위 검토에는 짧은 결과 요약과 선택된 생성 파일 manifest를 전달한다. 원문·전체 대화·전체 결과를 매번 복제하지 않는다. 기존 안전한 파일명·경로 제한을 재사용한다. 결과가 크면 조용히 잘라내지 말고 일부 검토 대상을 명시적으로 선택하거나 사용자 확인 상태로 전환한다. 파일명 충돌은 역할/실행 ID별로 구분하고 동일 파일 중복 저장을 방지한다.

## 화면

상위 작업에서 두 하위 역할, 제공자, 요청 모델, 배정 이유, 진행 상태, 검증 결과를 확인한다. 요청 모델과 확인된 실행 모델을 분리한다. 한쪽 완료/다른 쪽 대기/사용자 중단을 각각 표시한다. 하위 작업은 부모 아래에 묶어 표시해 일반 작업 목록을 불필요하게 늘리지 않는다. 전체 중단과 실패한 작업만 재개를 제공한다.

## 완료 기준

1. 배정 저장 중 오류 시 부분 생성 없음.
2. 중복 배정·동시 claim·완료 재전송에도 실행 및 상위 검토 중복 없음.
3. 하위 1개 실패 후 해당 작업만 재개하고 완료한 작업의 실행 횟수는 유지.
4. 상위 중단·취소·새 지시 이후 과거 결과와 claim 차단.
5. PC 오프라인에서도 Claude 결과 보존, PC 복귀 후 Codex 실행 및 검토 재개.
6. 잘못된 모델·effort·파일 manifest와 과도한 작업 수·용량 차단.
7. 실제 작은 구독 시험에서 양쪽 하위 결과를 한 마스터가 검토하여 한 작업에 최종 반환.
8. 테스트 통과와 별개로 실제 모델/사용량의 관측 범위를 기록하고 토큰 절감률·품질 동등성을 미리 주장하지 않음.

## 다음 범위

첫 구현 검증 뒤에 가변 하위 작업 수와 의존 관계, 원문 첨부의 임시 전달, 모델별 실제 사용량 계측을 확장한다. 이 문서가 그것들의 구현 완료를 뜻하지 않는다.
