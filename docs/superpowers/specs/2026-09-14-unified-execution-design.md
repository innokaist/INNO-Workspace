# 1단계: 클라우드 공통 작업 기록과 데스크톱 실행 연결

작성: 2026-09-14. 상태: 구현 전 검토안.

## 목적
휴대폰에서 만든 작업을 켜져 있는 데스크톱 Codex가 수행하고, 답변·생성 파일·진행 상태를 같은 클라우드 작업에 반환한다. Claude도 동일 작업의 최신 대화와 체크포인트를 이어받는다. 개발 위치는 E:\Develop\INNO Workspace다.

## 구조 선택
1. 클라우드 기준 기록 + 데스크톱 실행 연결(추천): 기존 D1의 작업 ID·버전·실행권을 재사용한다. 기기 간 기록 충돌이 적고 외부에서 PC로 접속하는 포트가 필요 없다. 인터넷 연결이 필요하다.
2. SQLite와 D1 양방향 복제: 오프라인 편집에 유리하지만 대화·산출물 병합과 실행권 충돌 처리가 복잡하다.
3. 수동 내보내기·가져오기: 구현은 단순하지만 연속 작업 요구를 충족하지 못한다.

## 동작 계약
- 클라우드 연결 모드에서는 D1이 공통 작업 기록이다. 기존 로컬 전용 기록은 보존하고 별도 모드임을 표시한다. 기존 기록을 무단 덮어쓰거나 삭제하지 않는다.
- 사용자가 Codex 실행을 선택하면 대상 작업을 실행 대기 상태로 기록한다. 연결된 데스크톱은 명시적으로 Codex 실행이 요청된 작업만 가져온다.
- 실행 연결 프로세스는 로컬에서 클라우드로 HTTPS 요청을 보낸다. PC에 외부 수신 포트를 열지 않는다. 기존 개인 토큰은 로컬 비밀 설정에서 읽고 프롬프트·로그·Git에 넣지 않는다.
- 한 데스크톱은 기본 한 작업을 수행한다. 여러 연결 프로세스가 경합해도 D1 버전 비교와 실행 ID·세대로 하나만 실행권을 획득한다.
- 실행 중에는 주기적으로 실행권을 갱신하고 사용자 중지·새 메시지·연결 오류를 확인한다. 실행권 상실 시 로컬 실행을 중지하며 이전 실행의 결과 쓰기를 거부한다.
- 결과는 실행 ID에 묶인 로컬 전송 대기 기록에 먼저 남긴다. 네트워크 복구 시 같은 작업에 중복 없이 전송한다. 서버의 중복 요청 식별과 실행권 검증으로 재전송을 처리한다.
- PC 종료 시 대기 작업은 보존한다. 이미 실행 중이던 작업은 실행권 만료 후 중단 상태를 표시한다. 완료 여부가 불명확한 작업을 무조건 자동 재실행하지 않는다.
- 입력 원본은 클라우드 대기열이나 전송 대기 기록에 저장하지 않는다. 첨부가 필요한데 해당 실행기에서 자료를 읽을 수 없으면 자료 재연결 필요 상태를 표시한다. 초기 연결은 자료 없는 작업과 데스크톱에서 직접 재연결한 자료로 검증한다.
- 클라우드 UI에 데스크톱 연결 상태, 마지막 접속 시각, 대기·실행·자료 필요 상태를 구분한다. Codex와 Claude 전환은 기존 실행을 정지하고 새 실행권으로 최신 작업을 이어받는다.

## 구현 단위
1. 실행 대기·연결 상태·실행권 갱신·중복 요청 방지 계약을 공통 모델과 D1에 추가한다.
2. 기존 Codex runner를 사용하는 데스크톱 연결 프로세스와 재전송 저장소를 만든다.
3. 클라우드 UI의 실행 선택과 연결 상태를 붙이고, 직접 재연결 자료의 일시 전달을 구현한다.
4. 통합 검증 후 기존 Cloudflare 배포와 GitHub에 반영하고 사용 가이드를 갱신한다.

## 완료 기준
- 클라우드 작업 생성 → 데스크톱 Codex 실행 → 클라우드 답변·파일 확인이 실제로 성공한다.
- 같은 작업에 연결 프로세스 두 개가 경합해도 실행은 하나다.
- 휴대폰 측 중지·추가 메시지가 이전 실행의 결과 등록을 차단한다.
- 일시 단절 후 답변·파일이 중복 없이 복구된다.
- 연결 끊김과 자료 미연결을 정상 실행으로 표시하지 않는다.
- 기존 Claude 왕복 실행과 로컬 전용 모드가 계속 동작한다.
- 입력 원본과 인증값이 작업 저장소·Git·진단 로그에 남지 않는 것을 검사한다.

## 후속 단계
이 단계 검증 후 중단·재개 정책, 연구 데이터 어댑터, 작업별 에이전트 구성, 사용량 표시, 전문 결과물 품질, 모바일 조작을 순서대로 확장한다. 구독 전체 사용량 조회 등 제공자가 노출하지 않는 정보는 추정값과 실측값을 구분한다. 무료 서비스 한도 내 운영을 유지한다.
