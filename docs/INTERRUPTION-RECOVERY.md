# 중단과 재개 안내

작업 상세의 저장된 재개 지점 아래에 중단 원인과 다음 행동을 표시합니다.

- 사용/요청 한도: 공식 사용량을 확인하고 한도가 회복되면 작업 실행을 누릅니다. HTTP 429는 요청 속도 제한일 수도 있습니다.
- 인증: Codex 구독 로그인 또는 Claude 연결을 확인하고 작업 실행을 누릅니다.
- 통신 또는 원인 미확인: 기존 실행과 생성된 결과를 먼저 확인합니다. 확인 후 작업 실행을 누릅니다.
- 데스크톱 연결 만료: 같은 PC 연결을 다시 실행하면 보관된 결과의 전달을 먼저 시도합니다. 작업을 변경하거나 새 실행을 시작하면 이전 실행 결과는 거절될 수 있습니다.
- 실행기/원본 연결 대기: 실행기 설정과 필요한 원본을 확인합니다. 원본 내용은 플랫폼에 영구 저장하지 않으므로 다시 연결해야 할 수 있습니다.

실패, 실행기 연결 대기, Claude 세션 시작, 데스크톱 연결 만료가 기존 checkpoint 내용을 덮어쓰지 않습니다. 최신 실패 분류 하나만 보관하며 원본 진단 로그를 클라우드로 저장하지 않습니다. 이 변경 이전에 이미 덮어써진 checkpoint는 복원하지 못합니다.

서버 Retry-After가 유효하면 재시도 안내 시각을 표시하지만 구독 한도 초기화 시각으로 간주하지 않습니다. 실제 실행 여부가 불명확한 작업의 자동 재실행은 현재 비활성화되어 있습니다. 보관된 결과 전달 재시도는 AI를 다시 호출하지 않습니다. 재개는 저장된 대화와 checkpoint를 새 실행에 전달하는 방식이며, 중단된 내부 추론 전체를 복원하지는 않습니다.

Codex 공식 [비대화형 실행 문서](https://learn.chatgpt.com/docs/non-interactive-mode)는 JSONL의 turn.failed/error 이벤트를 설명하지만 이 문서에서 구독 초기화 시각이나 부작용 없는 재실행을 보장하는 계약은 확인되지 않았습니다. 분류가 불가능한 오류는 원인 미확인으로 남깁니다.

검증: 합성 오류·시간 이동을 이용한 SQLite/D1/Worker/desktop 회귀 테스트와 로컬 브라우저 화면 점검. 실제 구독 한도를 소진하는 시험은 하지 않았습니다.
