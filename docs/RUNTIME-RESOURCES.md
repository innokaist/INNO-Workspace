# 실행 중 자원 누적 관리

Codex 실행기의 표준 출력을 JSONL 단위로 처리합니다. 마지막 답변, 스레드 식별자, 사용량, 실패 판정에 필요한 이벤트만 메모리에 남기고 도구 실행 로그와 이전 중간 답변은 누적하지 않습니다. 최종 답변과 생성 파일 처리 방식은 유지됩니다.

- 단일 이벤트 상한: UTF-16 문자 단위 16 Mi. 초과 시 결과를 잘라 성공 처리하지 않고 실행을 중단합니다. 프로세스 종료를 확인한 후 실패를 전달합니다.
- 진단 출력: 마지막 64 Ki 문자만 메모리에 유지합니다. 원문 로그를 클라우드 실패 기록에 저장하지 않습니다.
- 정상적으로 프로세스 종료 결과를 수집한 뒤: 해당 실행 폴더가 완전히 비어 있으면 비재귀 방식으로 제거합니다. 파일이나 하위 폴더가 있으면 그대로 보존합니다. 권한 문제로 정리할 수 없으면 결과 전달을 우선합니다.
- 강제 종료·출력 상한 중단 등 정상 수집 전에 빠져나온 경로의 빈 폴더는 남을 수 있습니다. 과거 실행 폴더를 일괄 삭제하지 않습니다.
- 기존 실행 폴더 점검(256 MiB / 5,000 항목)과 단일 결과 재전송 파일은 유지됩니다. 이 점검은 새 작업 시작 전의 확인이며 실행 중 전체 디스크 사용량을 강제로 제한하지 않습니다.

이는 INNO 출력 수집기의 누적을 줄이는 변경입니다. Codex와 하위 도구 전체의 메모리·디스크를 강제로 제한하는 기능은 아닙니다. 장시간 실행 파일 정리, 디스크 상태 표시, 사용자가 검토한 결과의 선택적 정리는 후속 과제입니다.
