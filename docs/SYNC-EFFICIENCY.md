# 동기화 전송 최적화

화면이 활성화되어 있을 때의 기존 5초 조회 주기는 유지합니다. 최초 연결은 전체 상태를 받고 이후에는 마지막 변경 번호를 since 쿼리로 보냅니다. 번호가 같으면 서버는 대화·첨부 메타데이터·결과물·사용량 기록을 다시 조회하거나 전송하지 않고 작은 상태 응답을 반환합니다.

변경이 있으면 전체 상태를 다시 받습니다. 변경된 작업만 받는 방식이나 실시간 푸시 기능은 아닙니다. 데스크톱 접속 여부, 실행기 지원 여부와 로컬 실행 상태는 변경 번호가 같아도 갱신합니다. 클라이언트는 변경 없는 응답에서 기존 작업 배열을 유지합니다. 화면은 기존 변경 감지에 따라 필요한 때만 다시 그립니다.

겹친 요청의 늦은 응답과 더 낮은 변경 번호는 최신 기록을 덮어쓰지 않습니다. DB를 과거 백업으로 되돌려 변경 번호가 낮아졌다면 화면을 새로고침하거나 서버 연결을 다시 설정해 새 동기화를 시작하세요. 변경 번호 없는 구형 서버에는 전체 조회 방식으로 연결합니다. 기존 API와 MCP의 since 없는 호출도 전체 상태를 반환합니다.

데스크톱 웹 프록시가 조건을 클라우드에 전달하므로 PC와 클라우드 사이에서도 변경 없는 전체 기록 전송을 생략합니다. 원본 파일 저장 정책과 작업 실행 방식에는 변화가 없습니다.
